# Model backends

What NoorVox can run, what each backend really supports, where its files live, and the licenses. Details and measurements:
[ADR-0001](adr/0001-kokoro-backend-and-worker-model.md) (Kokoro, workers) and [ADR-0002](adr/0002-qwen3-tts-and-gpu.md) (Qwen3-TTS, GPU).

| | Kokoro 82M | Qwen3-TTS 1.7B CustomVoice | Qwen3-TTS 1.7B Base | 0.6B CustomVoice / Base |
|---|---|---|---|---|
| Runs on | CPU (GPU optional) | NVIDIA GPU (CUDA) | NVIDIA GPU | NVIDIA GPU |
| Voices | 54 voice files + your blends | 9 built-in speakers | your cloned voice profiles | 9 speakers / your clones |
| Controls | voice, speed | voice, **style directions**, language, seed | cloned voice, language, seed | voice / clone, language, seed |
| Speed on the dev PC (RTX 3080) | 6× real time on CPU, ~15× on CUDA | ~2.6× real time warm | ~2.5× real time warm | not measured yet |
| Download | 391 MB | 4.5 GB + 5.2 GB engine (once) | 4.5 GB + engine | 2.5 GB + engine |

## Kokoro-82M

| | |
|---|---|
| Backend id | `kokoro-onnx` |
| Library | KokoroSharp 0.8.4 (MIT) → ONNX Runtime 1.22 (MIT); CPU provider by default, CUDA optional |
| Phonemizer | MisakiSharp (Apache-2.0). espeak-ng is **not** used or shipped. |
| Model package | `kokoro-82m@1.0`: `kokoro.onnx` fp32, 325,508,342 bytes, sha256 `0cfd5e79aab70a3d8c1a57dc639835110ddb32c9f5ff4fdd1f4db202ea43bb05` |
| Voice pack | `kokoro-82m-v1.0-voices`: 54 voices (`voices/*.npy`), each sha256-listed in the catalog |
| Source | github.com/Lyrcaxis/KokoroSharpBinaries release v2.0.0 (weights and voices identical to hexgrad/Kokoro-82M v1.0 as converted by KokoroSharp) |
| License | Model and voices: **Apache-2.0** (hexgrad/Kokoro-82M). Commercial use is allowed under Apache-2.0; keep the license notice when redistributing the files. |
| Output | 24 kHz, mono, 16-bit PCM WAV |
| Languages (by voice prefix) | `a` American English (20 voices), `b` British English (8), `j` Japanese (5), `z` Mandarin (8), `e` Spanish (3), `f` French (1), `h` Hindi (4), `i` Italian (2), `p` Brazilian Portuguese (3) |

### Capabilities as exposed

| Control | Supported | Notes |
|---|---|---|
| Voice | yes | any installed voice id |
| Speed | yes | 0.5–2.0 |
| Voice mixing | yes (0.2.0) | `voices blend` / Blend voices…: weighted average of 2–4 voices, saved as an immutable custom voice |
| Pitch, emotion, style | **no** | not controls in Kokoro, so NoorVox doesn't show them |
| Loudness | export only | peak normalisation in `export assemble` |
| Phoneme timestamps | library supports it | not used: subtitles are segment-level |
| Deterministic output | **no** | identical inputs can differ by a few samples, so takes are identified by inputs (cacheKey), not audio hashes |

### Performance (measured on the development PC: Windows 10, RTX 3080)

| | |
|---|---|
| Model load | ~4 s from a cold disk, ~1 s when cached by the OS |
| Synthesis | about 6× faster than real time on long passages (20 s of audio in ~3.4 s); short sentences have ~1–2 s of fixed overhead |
| Memory | worker ~1.0 GB with the model loaded; ~46 MB after Unload (process recycle) |
| CUDA (0.3.0) | warm real-time factor 0.065–0.07 (~15×) through NoorVox, vs 0.17 on CPU; first call ~4 s (CUDA initialisation) |

### GPU (0.3.0, opt-in)

`noorvox gpu set --kokoro cuda` or Settings → Voice engine → *Run Kokoro on*. The worker then loads ONNX Runtime's GPU build from the
`onnxruntime-cuda` engine pack (official NuGet DLLs, sha256-checked) and CUDA 12.8 / cuDNN 9 from the `qwen-tts` engine's PyTorch folder,
through a DLL resolver set before any ONNX Runtime call. If a pack is missing or CUDA fails, Kokoro runs on the CPU and the worker says why;
the Monitor shows the real provider. Same speech as CPU (envelope correlation 0.998). DirectML remains unusable (ADR-0001).
ONNX Runtime doesn't report GPU memory, so the Monitor shows "unavailable" for Kokoro on CUDA.

## Qwen3-TTS (0.3.0)

| | |
|---|---|
| Backend id | `qwen3-tts` |
| Engine | `qwen-tts` engine pack: private Python 3.12.10, PyTorch 2.11.0+cu128, faster-qwen3-tts 0.5.4 (CUDA graphs), transformers 5.15.1, installed from a hash-locked list (`src/NoorVox.Core/Engines/qwen-tts.lock`, generated by `tools/gen_engine_lock.py`) |
| Process | `NoorVox.Worker` starts `engines\qwen\noorvox_qwen.py` with the engine's Python (`-I`, offline: `HF_HUB_OFFLINE=1`), JSON lines on stdin/stdout, in a kill-on-close Job Object. The worker supervisor, IPC, Monitor and Stop/Unload are the same as for Kokoro. |
| Models | `qwen3-tts-1.7b-customvoice`, `qwen3-tts-1.7b-base`, `qwen3-tts-0.6b-customvoice`, `qwen3-tts-0.6b-base`, each a Hugging Face snapshot at a pinned revision, every file sha256-listed |
| License | Models **Apache-2.0** (Qwen). Engine: Python PSF, PyTorch BSD-3, transformers/qwen-tts Apache-2.0, faster-qwen3-tts MIT, NVIDIA CUDA/cuDNN under NVIDIA's EULA inside the PyTorch wheel |
| Output | 24 kHz mono 16-bit WAV (float output scaled only if it would clip) |
| Languages | `auto`, English, Chinese, Japanese, Korean, German, French, Russian, Portuguese, Spanish, Italian |

### Capabilities as exposed

| Control | CustomVoice 1.7B | CustomVoice 0.6B | Base (cloning) |
|---|---|---|---|
| Voice | 9 speakers: Aiden, Ryan (English), Vivian, Serena, Uncle Fu, Dylan, Eric (Chinese), Ono Anna (Japanese), Sohee (Korean); all can speak every language | same | your voice profiles |
| Style directions | **yes**: free text, e.g. "Calm, warm documentary narration with a hint of humour. Speak slowly." | no (ignored by the model, so not offered) | no |
| Speed | **no**: ask for a pace in the style | no | no |
| Seed | yes: same seed + text + settings on the same GPU and engine = byte-identical WAV (verified) | yes | yes |
| Language | yes (`auto` by default) | yes | yes (default: the profile's language) |

### Voice profiles (cloning) and consent

`noorvox voices clone` or *Clone a voice…* in Quick Narration. A profile is a **copy** of a 2–60 s WAV plus its transcript, stored in
`<models>\voice-profiles\<voiceId>\` with its sha256, the original file *name* (not its path), and the consent statement the user
confirmed ("This recording is my own voice." or "I have the speaker's permission…"). Profiles are immutable; delete one with
`voices remove-profile`. Takes, quick-narration manifests and `synth` output record `voiceKind: clone`. Only local files can be used.

### Performance (RTX 3080 10 GB shared with other apps, HDD model storage)

| | |
|---|---|
| Model load (1.7B) | 81 s from an HDD, including CUDA-graph warm-up (measured once; faster storage loads faster) |
| First synthesis after load | +5–10 s one-time graph capture for a new shape |
| Warm synthesis | real-time factor 0.38–0.41 (2.5–2.6× faster than real time) |
| GPU memory | ~4.5 GB allocated, ~4.9 GB reserved by PyTorch (reported live in the Monitor, source `torch.cuda`) |
| Engine process memory | ~2.2 GB working set (Python + PyTorch + CUDA) on top of the worker |
| Long text | split at sentence ends into ≤600-character chunks inside the engine; segments in projects are usually shorter |

## Chatterbox (0.4.0)

| | |
|---|---|
| Backend id | `chatterbox` |
| Engine | `chatterbox` engine pack: private Python 3.12.10, PyTorch 2.6.0+cu124, chatterbox-tts 0.1.7, hash-locked (`src/NoorVox.Core/Engines/chatterbox.lock`). Separate from Qwen's because it pins an older PyTorch. |
| Process | `engines\chatterbox\noorvox_chatterbox.py` in the worker's child Python, on the same `PythonSidecarBackend` as Qwen (Job Object, JSON lines, load stages, GPU numbers). |
| Models | `chatterbox-english`, `chatterbox-multilingual` (23 languages), `chatterbox-turbo`, pinned Hugging Face revisions, only the files each loader reads (3.0–3.2 GB each) |
| License | Models and code **MIT** (Resemble AI) |
| Output | 24 kHz mono 16-bit WAV, **always watermarked** (Resemble AI Perth, inaudible), reported as `watermark: "perth"` |

| Control | English | Multilingual | Turbo |
|---|---|---|---|
| Voices | `default` (built-in) + every voice profile from its reference audio (no transcript needed) | same | same |
| Emotion (`exaggeration`) | 0.25–2.0, default 0.5: flat → dramatic; higher is also a bit faster | same | no (ignored by the model) |
| Pace (`cfg_weight`) | 0.1–1.0, default 0.5; lower is gently slower (0.1 ≈ 12% slower than 1.0). 0.0 crashes the model, so it isn't offered. | same | no |
| Language | English only | 23 languages | English |
| Seed | yes (same seed → identical WAV, verified) | yes | yes |

Performance (RTX 3080, measured): English/Multilingual ≈ real time (RTF 1.0–1.3) at 3.5 GB peak GPU memory; Turbo ≈ 2× real time
(RTF ≈ 0.5) at 3.1 GB. Cold loads from an HDD took 1.5–4 minutes. Try emotion 0.7+ with pace 0.3 for dramatic reads. See
[ADR-0003](adr/0003-chatterbox.md).

## Model and voice files on disk

```text
<models>\kokoro-82m\1.0\
  kokoro.onnx
  noorvox.model.json            model manifest (written last = install complete)
  voices\af_heart.npy …         54 voices
  voicepacks\kokoro-82m-v1.0-voices.json
  voicepacks\custom-voices.json  your blends (sha256 listed, verified like official voices)
  voices\<id>.blend.json         recipe of each blend
```

Qwen models live next to it (`<models>\qwen3-tts-1.7b-customvoice\1.0\…` with `config.json`, `model.safetensors`,
`speech_tokenizer\…`), engine packs in `<models>\engines\<id>\<version>\` and voice profiles in `<models>\voice-profiles\`.

- Install: `noorvox models install kokoro-82m` or the studio's first run / Models page. Download → `<cache>\staging` → sha256 check → move.
- Import offline copies: `noorvox models import --from DIR`. Weights must match a catalog hash.
- Verify: `noorvox models verify` (sha256) or **Verify files** in the studio.
- Updates install side by side; older versions stay because takes record the model sha256 they were made with.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `model_not_installed` | `noorvox models install kokoro-82m`, or point the models folder at an existing install (Settings → Storage). |
| `verification_failed` after a download | Run the install again: partial files are deleted and the download restarts or resumes. |
| A voice sounds wrong for the language | The language follows the voice prefix (`bf_…` is British English). Pick a voice for the script's language. |
| A segment says nothing | Text with nothing pronounceable in the voice's language (e.g. only symbols) produces no audio and fails with `synthesis_failed`. |
| Names mispronounced | Add a replacement in the project's `voices\pronunciation.json`, e.g. `NoorEngine` → `Noor Engine`. |
| `engine_not_installed` | `noorvox engines install qwen-tts` (installing a Qwen model does this automatically). |
| `gpu_required` | Qwen needs an NVIDIA GPU that PyTorch can use. `noorvox gpu status` shows what the engine detected. |
| `gpu_out_of_memory` | Close GPU-heavy apps (3D, games) or use a 0.6B model; Unload other Qwen workers in the Monitor. |
| Qwen load takes minutes | Expected on an HDD (4.5 GB read + CUDA-graph capture). Keep the worker warm (`--keep-worker`, the studio does). |

## Adding a backend (for developers)

1. Implement `ITtsBackend` (`src/NoorVox.Core/Backends/Contracts.cs`) in a new `NoorVox.Backends.<Name>` project, and map its backend id
   in `NoorVox.Worker/Program.cs`. A Python model follows `NoorVox.Backends.Python`: a sidecar script shipped with the worker, an engine pack
   with a hash-locked lock file, `IBackendResources` for GPU/sidecar numbers.
2. Load it **only** in a worker process; the supervisor and IPC stay the same.
3. Declare truthful `capabilities` for each catalog model (`Core/Models/Capabilities.cs`); the CLI and UI accept and show only what's `true`.
4. Add the model package(s), voice packs and engine, with sha256 and license, to `catalog.json` (`tools/gen_catalog.py`).
5. Candidates noted so far: Chatterbox (MIT, cloning + emotion, ~0.5B), Kitten TTS (tiny CPU model), Piper (fast CPU voices; check each voice's license).
